# Спецификация требований к программному обеспечению (SRS)
## Проект: Консольный менеджер задач «TaskTracker C++» (Вариант 4)

---

### 1. Введение (Introduction)
#### 1.1 Назначение (Purpose)
Настоящий документ описывает бизнес-требования, функциональные и нефункциональные требования к программному обеспечению «TaskTracker C++» — консольному/десктопному приложению для управления личными и рабочими задачами.

#### 1.2 Границы проекта (Scope)
Приложение «TaskTracker C++» предназначено для локального управления списками дел. Система поддерживает древовидные подзадачи, дедлайны, уровни приоритетов, категории (теги), а также механизм автоматического создания повторяющихся задач (дневные, недельные, месячные).

#### 1.3 Язык разработки и технологии
- **Язык разработки:** C++ (C++17 / C++20)
- **Среда разработки:** Microsoft Visual Studio / GCC (Linux/Windows)
- **Язык спецификации требований и UI-прототипирования:** SysMLv2 / Markdown
- **Хранение данных:** Локальные файлы JSON / CSV

### 2. Бизнес-требования (Business Requirements)
#### 2.1 Бизнес-цели (Business Goals)
- **БЦ-1:** Предоставить пользователю легкий, автономный и быструю систему учета задач без необходимости постоянного подключения к сети Интернет.
- **БЦ-2:** Минимизировать время, затрачиваемое на оперативное планирование дня (добавление задачи менее чем за 5 секунд через удобный CLI/TUI интерфейс).
- **БЦ-3:** Обеспечить 0% утери регулярных рутинных задач за счет встроенного движка рекуррентных (повторяющихся) событий.

#### 2.2 Целевая аудитория (User Classes)
- **Персональный пользователь / Студент:** Использует приложение для отслеживания дедлайнов по учебе, личных дел, бытовых покупок.
- **IT-разработчик / Инженер:** Ценит минимализм, скорость консольного интерфейса, хранение данных в открытом текстовом формате.

### 3. Функциональные требования (Functional Requirements)

#### 3.1 Управление задачами и подзадачами (Task & Subtask Management)
- **ФТР-1.1 (Создание):** Система должна позволять создавать задачу с указанием названия, подробного описания, категории и приоритета (Low, Medium, High, Critical).
- **ФТР-1.2 (Иерархия):** Пользователь должен иметь возможность создавать неограниченную вложенность подзадач (Subtasks).
- **ФТР-1.3 (Статусы):** Задача и подзадача могут находиться в состояниях: `Pending` (Запланировано), `In Progress` (В процессе), `Completed` (Завершено), `Cancelled` (Отменено).
- **ФТР-1.4 (Авто-статус parent-задачи):** При завершении всех подзадач родительская задача автоматически предлагает изменить свой статус на `Completed`.

#### 3.2 Дедлайны и повторяющиеся задачи (Deadlines & Recurring Tasks)
- **ФТР-2.1 (Дедлайны):** Каждой задаче можно задать точные дату и время завершения (`YYYY-MM-DD HH:MM`).
- **ФТР-2.2 (Повторение):** Поддержка правил повторения: `Daily` (Ежедневно), `Weekly` (Еженедельно), `Monthly` (Ежемесячно), `Custom` (Каждые N дней).
- **ФТР-2.3 (Генерация копий):** При отметке повторяющейся задачи как `Completed` система автоматически создает следующую задачу на следующий период.

#### 3.3 Категории, фильтрация и поиск (Categories & Search)
- **ФТР-3.1 (Категоризация):** Привязка задач к категориям (например, `#Учеба`, `#Работа`, `#Личное`).
- **ФТР-3.2 (Фильтрация):** Отображение задач по категориям, уровню приоритета, наличию просроченного дедлайна.
- **ФТР-3.3 (Сортировка):** Сортировка списка по дате дедлайна, дате создания, приоритету.

### 4. Графическая часть и Прототипирование GUI (SysMLv2 & Wireframes)

#### 4.1 Структура системы в SysMLv2 (System Structure)
```sysml
package TaskTrackerSystem {
    enum Priority { LOW; MEDIUM; HIGH; CRITICAL; }
    enum Status { PENDING; IN_PROGRESS; COMPLETED; CANCELLED; }
    enum RecurrenceType { NONE; DAILY; WEEKLY; MONTHLY; }

    part def Task {
        attribute id : String;
        attribute title : String;
        attribute deadline : String;
        attribute priority : Priority;
        attribute status : Status;
        attribute recurrence : RecurrenceType;
        
        part subtasks : Task[*];
    }

    part def Category {
        attribute categoryName : String;
        part tasks : Task[*];
    }

    part def TaskManager {
        perform action addTask();
        perform action completeTask();
        perform action filterByPriority();
        perform action generateRecurring();
    }
}
